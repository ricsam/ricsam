01 / THE STORY

One problem, then a system.

My public trail starts with changing interfaces and ends—so far—with changing what software is allowed to do. The scale grew. The habit stayed the same: expose the hidden state, draw a clear boundary, and make the difficult part reusable.

  1. 2012

    Make the interface tangible.

    Page Painter let people draw directly on web pages. Hot Corn Dog made GNOME’s hot corners configurable. The first projects were small ways to make a computer fit the person using it.

  2. 2015—18

    Use software to model real work.

    Student-union systems, scientific models, small web products, machine-learning labs, and JavaScript-driven Terraform moved the work from interface tweaks toward data and operations.

  3. 2019—24

    Extract the hard part.

    React animation and collapse components, filesystem abstractions, JSONC tooling, and a job scheduler became focused libraries instead of one-off application code.

  4. Now

    Compose the primitives.

    The current work is a set of connected systems: portable storage and jobs, spreadsheet-grade data interfaces, a typed Bun/React web stack, and constrained runtimes for agents.

“The code changed. The through-line did not: capability should be explicit, state should be inspectable, and useful pieces should compose.”

02 / SELECTED SYSTEMS

Four stacks, not 130 tabs.

A concise map of the projects that best explain how I think and build.

SYSTEM 01

Files / work

Files should not care where they live.

Nafs presents a Node-style filesystem over memory, disk, S3, and Enstore. Enstore turns that idea into an authenticated, streamable network filesystem. Enschedule adds durable PostgreSQL-backed jobs and routes worker logs through the same portable filesystem boundary.

  • enstore
  • nafs
  • enschedule

One familiar API. Local or remote. Scheduled or ad hoc.

SYSTEM 02

Data / interaction

A data grid should behave like an instrument.

React TanStack Table UI renders large, virtualized, skinnable tables. Selection Manager supplies spreadsheet-grade keyboard, mouse, editing, fill, and clipboard behavior. Formula Engine is building the sparse workbook model underneath it.

  • table UI
  • selection
  • formulas

Rendering, interaction, and calculation remain separate.

SYSTEM 03

Web / contracts

Types should survive the network.

Richie RPC carries Zod contracts from Bun servers to fetch clients, OpenAPI, streaming, SSE, WebSockets, and React Query. Richie Router adds generated, type-safe file routes without making the backend execute frontend modules. Together they form the web spine now used by Enschedule and my current AI platform work.

  • richie-rpc
  • richie-router
  • Bun + React

One contract, fewer translation layers.

SYSTEM 04

Agents / boundaries

Give agents tools, not the machine.

Agentic Web Research combines metasearch, browser rendering, and model-guided exploration behind a streaming API. Isolate provides capability-controlled V8 runtimes; Shell DSL provides in-process, POSIX-inspired pipelines without default host OS access. Together, they explore a safer execution model for software that can act.

  • research
  • isolate
  • shell-dsl

Useful capability, explicit policy, bounded execution.
