# Richie / `ricsam`

I build tools that make complex systems feel predictable.

My work usually starts with a concrete problem, finds the reusable primitive inside it, then follows that primitive until the pieces form a stack.

## Four systems

### Portable files and work

[`enstore`](https://github.com/ricsam/enstore) · [`nafs`](https://github.com/ricsam/nafs) · [`enschedule`](https://github.com/ricsam/enschedule)

An authenticated network filesystem, one Node-style API across storage backends, and durable PostgreSQL-backed jobs.

### Spreadsheet-grade data interfaces

[`react-tanstack-table-ui`](https://github.com/ricsam/react-tanstack-table-ui) · [`selection-manager`](https://github.com/ricsam/selection-manager) · [`formula-engine`](https://github.com/ricsam/formula-engine)

Virtualized table rendering, keyboard and pointer interaction, and a sparse workbook model.

### A typed Bun/React web stack

[`richie-rpc`](https://github.com/ricsam/richie-rpc) · [`richie-router`](https://github.com/ricsam/richie-router)

End-to-end contracts, OpenAPI and streaming, plus generated file routes with a strict frontend/backend boundary.

### Agents with boundaries

[`agentic-web-research`](https://github.com/ricsam/agentic-web-research) · [`isolate`](https://github.com/ricsam/isolate) · [`shell-dsl`](https://github.com/ricsam/shell-dsl)

Model-guided web research, capability-controlled V8 runtimes, and in-process shell pipelines without default host OS access.

## The short version

My public code starts in 2012 with browser and desktop extensions, moves through scientific models, web products, infrastructure automation, and React libraries, and arrives at the connected systems above.

The code changed. The habit did not: expose hidden state, keep boundaries explicit, and make the hard part reusable.
